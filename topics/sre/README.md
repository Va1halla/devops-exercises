# Site Reliability Engineering

## Вопросы по SRE

<details>
<summary>Что такое SLI (Service-Level Indicator)?</summary>
<b>
SLI (индикатор уровня сервиса) — это измерение, используемое для оценки фактической производительности или надёжности сервиса. Он служит основой для определения SLO.

Примеры:
- Задержка запросов
- Пропускная способность обработки
- Количество неудачных запросов за единицу времени

Подробнее: [Google SRE Handbook](https://sre.google/sre-book/table-of-contents/)
</b>
</details></br>

<details>
<summary>Что такое SLO (Service-Level Objective)?</summary>
<b>

SLO (целевой уровень сервиса) — это целевое значение или диапазон значений уровня сервиса, измеряемого с помощью SLI

Пример: 99% за 30 дней для определённого набора SLI.

Стоит также отметить, что SLO служит и нижней границей: это означает, что не требуется быть надёжнее, чем необходимо, поскольку это может задержать выпуск новых функций.

Подробнее: [Google SRE Handbook](https://sre.google/sre-book/table-of-contents/)
</b>
</details><br>

<details>
<summary>Что такое SLA (Service-Level Agreement)?</summary>
<b>

SLA (соглашение об уровне сервиса) — это формальное соглашение между поставщиком услуг и клиентами, определяющее ожидаемое качество сервиса и последствия его несоблюдения.

SRE обычно не участвует в составлении SLA, поскольку SLA тесно связаны с бизнес- и продуктовыми решениями

Подробнее: [Google SRE Handbook](https://sre.google/sre-book/table-of-contents/)
</b>
</details><br>

<details>
<summary>Что такое Error Budget?</summary>
<b>

Error Budget (бюджет ошибок) — это допустимый объём простоя или ошибок, который может испытывать сервис, продолжая соответствовать своему SLO.

Бюджет ошибок равен 1 минус SLO сервиса. У сервиса с SLO 99.9% бюджет ошибок составляет 0.1%.

Если сервис получает 1 000 000 запросов за четыре недели, SLO доступности 99.9% даёт бюджет в 1 000 ошибок за этот период.

Бюджет ошибок — это механизм балансирования между инновациями и стабильностью. Если SRE не может обеспечить соблюдение бюджета ошибок, вся система разваливается.

Подробнее: [Google SRE Handbook](https://sre.google/sre-book/table-of-contents/)
</b>
</details></br>

<details>
<summary>Что такое Toil?</summary>
<b>

Toil (рутина) — это работа, которая, как правило, выполняется вручную, повторяется, поддаётся автоматизации, носит тактический характер, не имеет долгосрочной ценности и растёт линейно по мере роста сервиса.

Если задачу можно автоматизировать, её, вероятно, стоит автоматизировать.

Автоматизация значительно сокращает Toil. Инвестиции в автоматизацию дают ценную работу с долгосрочным эффектом и обеспечивают возможность масштабирования с минимальными доработками по мере роста системы.

Подробнее: [Google SRE Handbook](https://sre.google/sre-book/table-of-contents/)
</b>
</details>
